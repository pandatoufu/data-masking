## 支持的文件格式与限制

| 项目 | 说明 |
| --- | --- |
| 纯文本 | 不限后缀，可无后缀，也可用 `.env`、`.gitignore` 等点文件（大小写不敏感） |
| 纯文本示例 | `txt`、`md`、`csv`、`json`、`yaml`、代码、日志（非穷尽） |
| 已知不支持 | `pdf`、`doc`/`docm`、`odt`、`rtf`、`ppt`/`pptm`/`pot`/`pps` 等旧或宏模板/放映格式、`xls`/`xlsx`、`pages`/`numbers`/`key` 及常见容器、程序和图片后缀；按名称拒绝，请转换或另存为 `.docx`/`.pptx` |
| 文档扩展名 | `docx`（Transitional / Strict 均可；拒绝宏文档、加密、数字签名包） |
| 演示文稿扩展名 | `pptx`（仅普通 Transitional / Strict 演示文稿；拒绝 `.ppt`、`.pptm`、模板/放映、加密、数字签名、未知批注家族） |
| 单文件大小 | 纯文本、DOCX、PPTX 共用默认 50 MiB（52428800 字节），可用既有 `max_file_size` 调整；显式旧配置优先 |
| 纯文本编码 | 含 NUL / UTF-16 拒绝；先严格检测 UTF-8，再严格检测 GBK，否则拒绝 |
| 换行 | 逐行保留 CRLF / LF，不做换行归一化 |
| DOCX 解压预算 | 最多 2048 个条目、所有部件实际解压总量最多 200 MiB（209715200 字节）、单 XML 部件最多 20 MiB、XML 嵌套最多 128 层 |
| PPTX 解压预算 | 与 DOCX 相同的独立预算：最多 2048 个条目、所有部件实际解压总量最多 200 MiB（209715200 字节）、单 XML 部件最多 20 MiB、XML 嵌套最多 128 层；仅接受 Store/Deflate |
| 词文件 | ≤ 1 MiB，每词 ≤ 256 字符，单次参与词数 ≤ 1000 |

名称策略是有限的已知格式集合，不是通用格式识别：未列出的后缀与无后缀文件按纯文本候选处理，再由大小与内容门禁决定；名称允许不代表内容已验证。二进制识别只依据 NUL / UTF-16 与严格编码链的启发式，不承诺识别所有二进制。纯文本只做字面替换，不保证代码或结构化数据替换后的语法有效。

### GUI 上传与临时资源边界

- 脱敏与还原的文档、粘贴内容在后端按有效 `max_file_size` 逐 part 限量读取，最多保留上限 + 1 字节用于超限判断，不会先把整个文档无界读完再拒绝。超限提示只给出上限，不伪造未保留的完整字节数。
- 词文件独立按 1 MiB 限量；规则关闭时仍静默忽略词输入，不因词超限报错。
- 正常 GUI 请求不会由应用把原文 multipart 写入临时文件；若兼容调用已预解析表单，其临时资源在请求结束前关闭并清理，清理失败以本地化提示替代本次结果。进程被强制终止、WebView 或操作系统内部缓存/落盘不在应用请求清理保证内。
- 手动 mapping 入口沿用既有解析接受范围，本次没有新增 32 MiB 业务硬限制；`mapping/` 快捷目录仍保留 32 MiB 传输保护。其他表单字段受独立协议预算保护，但本变更不承诺所有请求字段都严格限量。
- 前端仍需完整持有待上传文件、处理后的响应 base64 及另存副本；mapping、WebView 与操作系统缓存的内存成本未包含在文档预算内。文件 50 MiB 与解压 200 MiB 都是功能边界，不是进程内存上限。

### 大文件资源与实测边界

50 MiB 文件上限与 200 MiB 解压预算是功能门禁，不是内存或耗时上限。一次显式测量（2026-10-26，Ubuntu 26.04 LTS / Linux 7.0.14 x86_64 / AMD EPYC 16 vCPU / 7.3 GiB RAM，Go 1.26.0，`go test -c -tags large` 的 headless 测试进程，未初始化 GUI/WebView；每样本 2 轮中位数，堆采样间隔 2 ms）得到：

| 样本（真实 50 MiB） | 去程+回程中位耗时 | MemStats.TotalAlloc 差值 | 采样 Go 堆峰值 |
| --- | --- | --- | --- |
| 纯文本 | 约 25.3 s | 约 577 MB | 约 420 MB |
| DOCX（媒体型） | 约 0.70 s | 约 1.86 GB | 约 618 MB |
| PPTX（媒体型） | 约 0.80 s | 约 1.87 GB | 约 638 MB |
| 10 MiB 纯文本基线 | 约 5.4 s | 约 115 MB | 约 64 MB |
| 10 MiB DOCX 基线 | 约 0.21 s | 约 373 MB | 约 125 MB |
| 10 MiB PPTX 基线 | 约 0.16 s | 约 379 MB | 约 115 MB |

- 上表同一进程测得的 OS 峰值 RSS（`/proc/<pid>/status` 的 `VmHWM`，50 ms 轮询）约 647 MB；GUI handler 路径另测 40 MiB 文本去程/回程、40 MiB DOCX 与超限请求，进程峰值约 760 MB。
- `TotalAlloc` 是累计分配量，不是峰值；Go 堆峰值是采样近似值，不含 WebView、操作系统缓存、mapping 与前端 `ArrayBuffer`/base64 副本。不得把任一项当作固定内存上限或性能承诺。
- 纯文本对大文件明显慢于 DOCX/PPTX（约 2.4 MB/s，规则扫描成本随文件增长），50 MiB 纯文本可能耗时几十秒；处理期间仍受单操作保护，不能并行提交。
- 尚未测量：Windows 原生 GUI/WebView、真实 Word/PowerPoint 生成的 50 MiB 样本、映射与前端缓冲在真实浏览器中的叠加、低内存机器与网络盘。不同硬件、Go 版本和样本内容会显著改变结果。

### PPTX 处理范围

- 双向处理幻灯片（含隐藏页与未被主序列引用但仍声明的页）、版式、幻灯片母版、备注页、备注母版与讲义母版中的原生文字，包括标题、正文、普通文本框、嵌套组合形状内的文本和原生表格单元格。
- 演讲者备注保留并参与去程/回程；批注及批注专用人员信息在文字扫描前清除，回程不会恢复批注。普通文稿作者属性不属于批注人员清理范围。
- 隐藏形状与 `Choice`/`Fallback` 两个存储分支都会扫描；计数表示存储出现次数，不等于屏幕显示次数。同一段落内跨 run 的号码会命中和还原，但段落、文本体、形状、单元格、硬换行与字段是硬边界，不跨边界拼接。
- 保留页面顺序/尺寸/背景、形状位置/尺寸/旋转/层级、表格网格与合并、主题、段落/run 属性、图片/媒体及动画/切换引用。跨样式命中使用首命中 run 的样式，未命中文字及属性保留。必要转义与 `xml:space` 差异不属于格式变化。
- **不检查也不承诺处理**：图表及其缓存/数据源、SmartArt、嵌入 Excel/OLE 对象、图片文字、属性、字段指令与链接目标，以及批注以外的审阅历史。这些部件保留原样，刷新数据/字段或某些动画可能重新引入未处理值；结果会显示未检查短摘要，不代表整包无敏感信息。
- 不保证替换后的换行、溢出、自动适应或跨 run 混合样式与原来完全一致，也不提供 PPTX 渲染。不支持纯文本回复回填 PPTX，也不做 DOCX/PPTX 互转。

## 规则与方案（profile）

六类规则：`phone`（中国大陆手机号）、`idcard`（18 位中国身份证号）、`email`、`ip`、`api_key`（`sk-`、`AKIA`、`ghp_`、`xox-` 等前缀）、`custom`（自定义词）。

| 内置方案 | 行为 | 开启规则 |
| --- | --- | --- |
| 全规则脱敏 / All rules（`strict`） | 开启六类规则，不等于绝对安全 | phone、idcard、email、ip、api_key、custom |
| 日常脱敏 / Balanced（`balanced`，默认） | 不处理邮箱、IP 与身份证号 | phone、api_key、custom |
| 仅密钥 / API keys only（`minimal`） | 仅处理 API Key | api_key |
| 自定义 / Custom | 单独开关六类规则并勾选本次自定义词 | 全部可调 |

三预设在界面中只读，需要调整时选择自定义。GUI 自定义方案内部使用 `__custom`；headless 的 `profile` 使用本机配置中的实际 key，见 [MCP 指南](mcp.md)。用户配置可覆盖同名预设，界面摘要与规则详情展示实际生效配置，不应只按方案名称判断范围。

- 扫描优先级：`custom` > `idcard` > `phone` > `email` > `ip` > `api_key`；命中区间被消耗，不重复替换。
- 边界守卫避免误伤普通单词，如 `risk-aware`、`task-off` 不会命中 `api_key`。

### 自定义词

- **字面量精确匹配、大小写敏感**，不是正则：`a.b` 只匹配 `a.b`，不匹配 `axb`。
- 两种入口：文本框手输、导入 TXT；按行分隔，每行先 trim，空行忽略，合并去重。
- 词文件 ≤ 1 MiB、每词 ≤ 256 字符、本次词表 ≤ 1000、合并参与集 ≤ 1000；超限整批拒绝并报行号，保留之前有效词表。
- 本次词默认全勾选，未勾选的不参与脱敏；`custom` 规则关闭时词区失效。
- 再次导入会替换上次文件词，保留手输词。搜索只过滤显示；搜索时批量选择只作用于搜索结果，清空搜索不改变勾选。
- 某词单次命中超过阈值（默认 20）时先预览确认。本次词可取消，常备词不可在该面板取消；确认后按当前勾选重新计算。
- GUI 使用 `config.json` 的 `custom_words` 常备词与显式 TXT 导入；不会自动扫描 `cards/`。headless 完全忽略 `custom_words`，只读取 `cards/` 直属 TXT，见 [MCP 词库规则](mcp.md#输入与规则)。

### 占位符

形如 `[PHONE_1]`，前缀与规则对应：

| 规则 | 前缀 |
| --- | --- |
| phone | `PHONE` |
| idcard | `IDCARD` |
| email | `EMAIL` |
| ip | `IP` |
| api_key | `APIKEY` |
| custom | `CUSTOM` |

同规则同一原文值在一次脱敏中始终使用同一占位符，编号按首次出现顺序递增。原文已有合法占位符文法时，预检会拒绝处理以避免碰撞。

## 脱敏

1. 启动应用，默认进入“脱敏”页。
2. 选择单个文件（纯文本不限后缀、可无后缀，或 `.docx`/`.pptx`），或从 `original/` 下拉菜单选择程序旁的直属文件。Windows 支持点击或拖入，Linux 仅支持点击选择；下拉需显式选中后才读取。
3. 选择方案：默认日常脱敏（`balanced`）；需精细控制时选择自定义，在规则详情和词列表中逐项勾选。
4. 可选：填写或导入自定义词，也可从 `cards/` 下拉选择单个 TXT 词卡；确认规则启用及本次勾选范围。
5. 执行脱敏；如遇高频词或残留确认，先检查提示再决定是否继续。残留提示包含定位和计数，不代表结果已安全。
6. 成功后保留脱敏副本和配对 mapping。工作区可用时自动保存；仍可分别另存。只保存其中一项时，另一项未保存状态会保留，无需重新处理。

DOCX 成功结果显示实际删除批注 / 接受修订的状态和数量，以及未检查内容的短摘要；PPTX 显示独立的批注/人员/部件/资源清理计数和未检查短摘要，不混用 Word 修订概念。常规完整边界见[首页](../README.md#安全与使用边界)，不在执行前常驻显示。纯文本编码可在处理详情查看。

## 还原

1. 进入“还原”页，从 `pending/` 下拉选择程序旁的直属文件、使用“选择还原文件”手动选择，或切换到文本入口粘贴回复；只提交当前激活入口。
2. 选择本机配对 `.mapping.json`（可从 `mapping/` 下拉选择直属 JSON、手动选择，或显式点击“使用当前映射”带入最近一次成功脱敏的 mapping）。后续脱敏不会静默替换已选映射；退出后会话映射不恢复。
3. 执行还原并保留结果；工作区可用时自动保存，也可另存。

- 占位符支持大小写 / 全角 best-effort 匹配；被模型改写或翻译掉的占位符无法找回。
- 未知占位符残留会给出提示，可能拿错 mapping，但不阻断保存。
- DOCX mapping 还原 DOCX 得到 `.docx`；粘贴文本得到 `.txt`；跨格式提示无法确证文本一致。
- PPTX 采用路径 A：PPTX 原件 → 脱敏 PPTX → 模型编辑 PPTX → 本地还原 PPTX。PPTX mapping 为 version 3，只接受同格式 PPTX 回复；PPTX mapping 还原文本/DOCX、旧文本/DOCX mapping 还原 PPTX 都会明确拒绝，不产生伪装扩展名的文件。PPTX 还原保留回复中的结构修改，只替换映射文字并给出文字参考差异提示。
- 还原只恢复映射文字；文本还原不恢复 Word 排版，PPTX 还原不恢复批注、原始模板、原 ZIP 字节或跨 run 混合样式分配。DOCX/PPTX 审阅历史及未处理范围见[安全边界](../README.md#安全与使用边界)。

## 保存与退出

- **显式另存**：各平台均保留原生对话框，可将产物保存到其他支持的本地位置。
- **自动保存**：Windows/Linux 工作区可用时，脱敏副本写入 `masked/`、mapping 写入 `mapping/`、还原写入 `restored/`，自动保存算作已保存。
- **重名不覆盖**：自动保存遇重名在词干后追加 `-N`（`-1`、`-2`…），脱敏副本与 mapping 共用后缀。手动另存不得覆盖已有文件，需另选文件名。
- **文件保护**：不覆盖源文件、已有文件或符号链接；并发创建目标也不能绕过保护。多个入口同时发布时只报告可重试忙态，不混配、不死等。
- **失败处理**：普通处理/写入失败不发布半成品目标，原件不覆盖；发布已成功但临时清理失败时，如实提示已保存及清理警告，不承诺断电时零残留或跨文件事务。
- **启动降级**：GUI 的五个自动保存必需目录中任一创建失败或被普通文件/链接占位，全部自动保存不可用，应用仍可启动并手动另存；`pending/` 由 GUI 独立补建，其失败只禁用对应快捷入口并就近提示，不改变自动保存判定；`.agent-state/` 不参与 GUI 判定。启动后单次写失败只影响该次，不改变整体可用性。
- **退出保护**：存在未自动保存且未手动保存的产物时确认退出；均已保存时静默退出。处理、写入或清理忙时阻止退出。切换视图不丢失结果；重新执行将替换未保存结果时先确认。

## 工作区目录

根目录固定为**程序 executable 所在目录**（`os.Executable()` 解析符号链接后的真实目录），不使用进程工作目录，也没有配置项。请将程序放在**用户可写且不在模型项目内**的目录，例如 Windows `C:\Tools\data-masking\`、Linux `~/opt/data-masking/`。

**GUI 五目录**：`cards/`、`masked/`、`mapping/`、`original/`、`restored/`，这五个目录的状态决定自动保存是否可用；GUI 另在程序目录独立补建 `pending/` 作为待还原文件快捷输入目录。headless 要求 `cards/`、`masked/`、`mapping/`、`original/`、`pending/`、`restored/`，即 **headless 六目录**。同址共享，分开放置则各自独立，不读取对方入口的私有记录。

| 目录 | 入口 | 用途 |
| --- | --- | --- |
| `cards/` | GUI + headless | GUI 不自动扫描或自动载入词库，只在用户显式选择时列举直属 TXT 并导入单个词卡；headless 在 custom 启用时自动读取直属 TXT，关闭时不读 |
| `original/` | GUI + headless | 用户放置待脱敏原件；GUI 只在用户显式选择时列举直属受支持文档并读取所选单个文件，不自动导入 |
| `masked/` | GUI + headless | 脱敏副本 |
| `mapping/` | GUI + headless | 配对明文映射，**仅本机还原，不外发**；GUI 可在还原页列举直属 JSON 并读取用户显式选择的单个文件 |
| `pending/` | GUI + headless | 暂存待还原文件：GUI 独立补建，仅列举直属受支持文档并在显式选择后读取单个文件，不识别任务、不读取 `.agent-state/`；headless 用于项目回复与任务配对 |
| `restored/` | GUI + headless | 还原结果 |

- 各入口幂等补缺，不清空、删除或重建已有内容；`pending/` 与 `.agent-state/` 的旧数据 **不会自动删除或清理**。
- 必需目录被普通文件、符号链接或 Windows reparse point 占位时不可用，不跟随链接写入：GUI 的五个自动保存目录按原规则降级（`pending/` 占位只使该快捷入口不可用），headless 按六目录明确失败。
- `.agent-state/` 为 headless 私有任务记录，不是业务目录或配置项；GUI 不创建、不读取、不修改，也不识别其中的任务或恢复历史。
- 无覆盖保存依赖硬链接（本地 NTFS / ext4 等）；FAT/exFAT 不支持时明确失败，需另选支持的本地目录，不回退为可能覆盖的写入。

## 固定目录快捷选择

- 脱敏页：`original/`（DOCX、PPTX 与纯文本候选）、`cards/`（单个 TXT 词卡）；还原页：`pending/`（DOCX、PPTX 与纯文本候选）、`mapping/`（JSON 映射）。四类入口与原有手动按钮、粘贴、“使用当前映射”并存。
- 文档候选沿用统一名称策略：普通/新后缀、无后缀与 `.env` 等点文件可列出，`pdf`/`rtf`/`xls`/`pptm` 等已知不支持格式不列出；名称允许不代表内容已验证，显式选中后仍由原编码、大小与 DOCX/PPTX 门禁校验内容。`cards/` 仍仅 TXT，`mapping/` 仍仅 JSON。
- 只列**直属**常规文件（扩展名大小写不敏感），不递归、不跟随符号链接 / Windows reparse point、不读取正文；点“刷新”只更新该列表，不重读当前文件，也不清空已载入输入或结果。
- 只有**显式选中**后才限量读取该单个文件，再交给原有导入/解析/multipart/确认/自动保存/另存链。列表与当前快照解耦：文件名从列表消失不代表已载入内容失效；初始不默认选择，占位/空列表/读取失败不会清空已载入文件。
- 选择与快照只在本次会话内存中，不写 `localStorage` / `sessionStorage`，重启不恢复。保存或处理忙时阻止刷新与再次选择，迟到响应不会覆盖较新的选择。
- 快捷读取上限：文档沿用配置的有效 `max_file_size`（默认 50 MiB），词卡 1 MiB；`mapping/` 快捷入口另设 **32 MiB 传输保护上限**，超限请改用“选择映射”手动选择（手动入口的接受范围不变，也未新增 32 MiB 业务硬限制）。超限、格式不符或内容非法仍由原业务校验拒绝。
- 这不是 MCP 任务管理器：GUI 不识别 job / attempt、不读取 `.agent-state/`、不自动配对 mapping、不合并 `cards/` 全部词卡，也不会把选中的文件复制进 `original/` 或 `pending/`。目录来源的 mapping 与手动选择一样需要配对确认，不冒充“使用当前映射”。

## 产物命名

| 产物 | 命名 |
| --- | --- |
| 脱敏副本 | `<原名>.masked.<扩展名>`，如 `notes.masked.txt`、`合同.masked.docx`、`报告.masked.pptx`；无后缀与单段点文件回退 `.txt`：`README.masked.txt`、`.env.masked.txt` |
| mapping | `<原名>.masked.mapping.json`，如 `README.masked.mapping.json`、`.env.masked.mapping.json`；DOCX 为 version 2，PPTX 为 version 3；`source_file` 保留真实输入名 |
| 还原 DOCX | `<源词干>.restored.docx` |
| 还原 PPTX | `<源词干>.restored.pptx`；空源名回退 `restored.pptx` |
| 还原文本 | `<源词干>.restored.<实际扩展名>`；粘贴、无后缀与单段点文件为 `.txt`，如 `README.restored.txt`、`.env.restored.txt` |

以上为 GUI 建议名；headless 按任务保存，见 [MCP 指南](mcp.md)。**mapping 含原文对照表，只在本机使用，绝不发给模型或上传在线服务。**
